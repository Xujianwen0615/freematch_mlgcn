## 2. 结果说明了什么问题（核心结论）

### 2.1 半监督并未逼近全监督（最关键）

- 全监督 A=0.780，最好的 SSL 只有 C=0.6015 / D=0.5849，差距约 **0.20**。
- 结论：在这类**小样本、强不平衡、领域专用**的 15 类数据集上，FreeMatch 伪标签法被结构性瓶颈卡住，
  无法用无标签数据补回“缺标签”的损失。

### 2.2 半监督增益**真实但很小**

- `H (0.5407) → D (0.5849)`：加入 80% 无标签数据只提升 **+0.044（约 8% 相对）**。
- 而“缺标签”的代价 `A − H = 0.780 − 0.541 = 0.239`。SSL 只补回缺口的 **约 18%**。
- 结论：**标签数量是主要矛盾，无标签数据是二阶因素。**

### 2.3 标签占比单调驱动性能（G 扫描）

5%→0.328、10%→0.467、20%→0.585、50%→0.662、100%→0.780。每档增量均为正，
说明**多标定数据始终有效**（任何一档都值得增加标注量）。

### 2.4 ASL 在此数据集上是**负收益**

- 全监督：BCE 0.780 > ASL 0.742（−0.038）。
- SSL：BCE( C )0.6015 > ASL( D )0.5849（−0.017），且 D 的 hamming（0.2635）明显更差。
- 原因：ASL 面向**百万级超长尾**多标签场景；对密集、小规模、20 倍不平衡的领域数据，
  其“不对称聚焦 + 硬裁剪 + 类别平衡”造成校准变差、过度抑制难例。

### 2.5 ML-GCN 图头在 SSL 场景下**几乎没有贡献**

`D(图头)0.5849 ≈ E(无图 GAP)0.5903 ≈ F(无GCN头 GMP)0.5748`，互差 < 0.02，
且完整的 D 甚至**略低于**无图的 E。原因：① 20% 标签下 `custom_adj.pkl` 相关性信号弱/噪声；
② 领域类别相关性本身弱；③ 图收益被泛化缺口淹没。

### 2.6 根本瓶颈：**类别不平衡 + 伪标签的长尾偏置**

- 即使 100% 监督的 A，per-class AP 也跨度极大：cable 0.955 → tools&materials 0.513 / container 0.601。
- SSL D 更严重：稀有类 AP 塌缩到 person 0.26、rescue 0.21、container 0.32、tools 0.27，
  而高频类（cable / metal fixture / indicator / tube）0.75~0.90。
- 训练日志佐证（`outputs/D_ssl_mlgcn_asl_resnet50/train.log`）：`util_ratio` 从 0.767 掉到 ~0.30
  （约 70% 伪标签被阈值丢弃），`unsup_loss` 反而从 0.31 升到 0.42 —— 即教师与学生**对尾部类互不一致**。
- mAP 是**逐类 AP 的平均**，稀有类低 AP 直接拖低整体 mAP；而 FreeMatch 伪标签几乎只对高频类可靠，
  稀有类既得不到无标签帮助，又被多数类淹没。

### 2.7 SSL 模型过预测、校准差

D 的 macro-R 0.73 / macro-P 0.42（A 为 R 0.66 / P 0.80），hamming 0.26 vs A 0.096。
即高召回、低精度，源于伪标签置信度塌缩后的阈值失衡（见 2.6）。

## 3. 需要复核的方法学混淆项（重要）

1. **迭代数与 `labeled_ratio` 耦合**：`train.py` 中
   
   ```python
   algo.num_train_iter = args.num_train_iter or (args.epochs * len(lb_loader))   # train.py:356
   ```
   
   `len(lb_loader)` 随 `labeled_ratio` 变化（ratio=0.05 时 labeled≈108 → 每 epoch ~13 个 batch），
   同 120 epoch 下**低 ratio 实际训练步数远少于高 ratio**，且 CosineAnnealing 的 `T_max`（`train.py:283`）也不同。
   → 低 ratio 的低 mAP 部分是**欠训练**，不纯粹是标签不足。**跑 ratio 扫描时应固定总迭代数。**

2. **seed 固定但切分概率不同**：`data/custom_dataset.py` 的 `split_by_prefix` 用 `int(len(g)*ratio)`，
   极小分组在低 ratio 下可能每分组至少保留 1 个标注样本（`max(1, ...)`），影响真实标注比例精度。

## 4. 改进建议（含“改哪部分代码/参数”）

按“预计收益 × 实施成本”排序。每一条给出**改动文件、函数/行、参数及建议值**。

### 4.1 直击类别不平衡（当前瓶颈，优先级最高）

**(1) 加强监督损失的类别再平衡**

- 位置：`mlgcn/freematch.py` → `FreeMatchMultiLabel._sup_loss()`（约 148–162 行）。
  当前实现：
  
  ```python
  class_weight = 1.0 / (self.label_hist.to(y_lb.device) * self.num_classes + 0.1)
  class_weight = class_weight.clamp(0.5, 5.0)      # 上限仅 5.0，压不住 20 倍失衡
  ```

- 建议：
  
  - 把上限 `5.0` 提高到 **20~30**（或去掉上限、改成归一化）；
  - 改用“有效样本数”公式：`class_weight[c] ∝ (1-β) / (1-β^{n_c})`（β 建议 0.999）；
  - 或直接减小平滑项 `+0.1`。

- 也可改成 `mlgcn/losses.py` 中 `WeightedBCEWithLogits`（112–141 行）的 `pos_weight`，
  在 `build_loss`（144–157 行）传入每类 `pos_weight = (负样本数 / 正样本数)`。

**(2) 稀有类过采样 / 类别均衡 batch**

- 位置：`train.py` → `build_loaders()`（222–257 行）对 `lb_loader` 构造 `WeightedRandomSampler`
  （权重 ∝ 1/该样本含稀有类的频次或 1/类频次）。
- 位置：`data/custom_dataset.py` 的 `collate_fn`（135–149 行）可注入类别均衡逻辑。

**(3) 换回/调优 BCE，替代 ASL**

- 位置：`configs/freematch_mlgcn.yaml`（或 `run_experiments.py:56` 的 D 覆盖字典）：
  `loss: "asl"` → `loss: "bce"`，并把 `use_class_balancing` 设 `true`。
- 位置：`mlgcn/losses.py` → `AsymmetricLoss.__init__`（33 行），若要保留 ASL，
  把 `gamma_neg=4.0` 调低（如 2.0）、`clip=0.05` 调高（如 0.1），弱化对难例的抑制。
- 实验已证明 BCE( C )=0.6015 > ASL( D )=0.5849，**优先用 BCE + reweight**。

**(4) 每类最优阈值 + AP 导向损失**

- 位置：`mlgcn/freematch.py` → `evaluate()`（244–265 行）与 `mlgcn/metrics.py` → `compute_metrics`
  （14 行，阈值默认 `threshold=0.5`）。可对每类在验证集搜索 F1 最优阈值。
- 若要直接优化 AP：在 `train.py` 的 `criterion`（342–344 行）替换为 **AP Loss / 多标签 ranking/listwise**
  损失（需新增实现，当前库无此损失）。

### 4.2 半监督管线本身（提升伪标签质量与利用率）

**(5) 降低/放宽阈值，提高 `util_ratio`（当前掉到 ~0.30）**

- 位置：`mlgcn/freematch.py` → `_per_class_threshold()`（112–117 行）：
  
  ```python
  thresh = torch.clamp(self.time_p * mod, 0.25, 0.90)   # 上限 0.90 太高
  ```
  
  建议把 `time_p` 初始值（`__init__` 里 `time_p_init=0.5`）降低到 0.3，
  并把阈值 clamp 下限/上限放宽（如 0.15~0.85）。

- 位置：`_update_threshold()`（119–137 行）：
  
  ```python
  q = torch.quantile(flat, 0.9)                       # 分位数太高
  self.time_p = torch.clamp(self.time_p, 0.6, 0.95)    # clip_thresh 下限 0.6 太高
  ```
  
  建议把分位数降到 0.6~0.7、clip 下限降到 0.4~0.5。

**(6) 抑制伪标签长尾偏置：加强熵正则“公平项”**

- 位置：`mlgcn/freematch.py` → `entropy_loss()`（33–67 行）：
  
  ```python
  class_weight = (1.0 / label_hist).clamp(max=5.0)         # line 56，上限仅 5.0
  loss = confidence_loss + fairness_weight * fairness_loss  # fairness_weight=0.05
  ```
  
  建议把 `class_weight` 上限去掉或提到 20+，并把 `fairness_weight` 从 0.05 提至 0.1~0.2。

- 位置：`__init__`（74 行）`lambda_e=0.005` 调大（如 0.02~0.05）；对应配置 `configs/...:29` 的 `lambda_e`。

- position：`_sup_loss` 的类别平衡也可与 `label_hist` 联动（确保采样与损失一致）。

**(7) 无标签一致性损失的置信度重加权**

- 位置：`mlgcn/freematch.py` → `train_step()`（177–240 行）的 `unsup_loss` 计算（218–222 行）：
  当前 `per_elem_unsup * mask` 为二值掩码。可改为按 `probs_x_ulb_w` 置信度做**软权重**
  （如 weight = 置信度^γ），衰减低置信伪标签、减少噪声累积。

**(8) 更稳的增强一致性与多视图**

- 位置：`train.py` → `build_transform()`（203–219 行）：
  - 更强/多 crop：在 `strong` 分支加 `transforms.RandomResizedCrop`，或参考 FixMatch 模式用**多个强增强视图**；
  - 加 `MixUp`/`CutMix`（需在各 collate/训练循环实现）。
- 位置：`data/custom_dataset.py` → `__getitem__`（113–132 行）返回弱/强视图，可扩展为多强视图。

### 4.3 模型与特征（图头换来 0 收益，值得重构）

**(9) 统一并升级 backbone**

- 位置：`configs/freematch_mlgcn.yaml:10` `backbone: resnet101`，或 `run_experiments.py` 传 `--backbone`。
  确认实际与配置一致（见 3.2）。进一步可换 **Swin-T / ConvNeXt**。
- 位置：`train.py` → `build_model_from_args()`（261–264 行）**硬编码 `feature_dim=2048`**：
  若换 resnet18/34（特征 512）会维度不匹配，需改成按 backbone 取值（参考 `mlgcn/models.py:243` 的 `prefix`）。

**(10) 重建 ML-GCN 的标签相关性图**

- 位置：`mlgcn/models.py` → `gen_A()`（39–55 行）与 `GCNResnet.__init__`（96–138 行）：
  - `t=0.4`（二值化阈值，`configs/...:13 gcn_t`）建议扫描 0.2~0.6；
  - 用**当前标注数据的共现矩阵**在运行期重建 adjacency（现用预生成 `custom_adj.pkl`），
    或改成**可学习/注意力式**标签相关性模块；
  - 邻接归一化/权重 `p=0.2`（`gen_A` 内）可调。
- 位置：`GCNResnet.__init__`（129–135 行）类嵌入 `inp` 来自 `custom_glove_word2vec.pkl`；
  领域术语（“anchoring equipment”“rescue equipment”）GloVe 向量可能很差，建议换 **CLIP 文本编码器**输出。

### 4.4 数据与训练策略

**(11) 增加（尤其尾部类）标注数据 / 主动学习**

- 位置：无代码改动，属数据侧。结果强烈表明标签是主瓶颈；配合主动学习优先标注**稀有/高不确定性**样本。

**(12) 更强的预训练 / 自监督预训练**

- 位置：`train.py` → `_backbone()`（`mlgcn/models.py:219–230`）：
  预训练权重可换更强来源（如 CLIP 图像编码器 / 自监督 MAE / BYOL），再微调。

**(13) TTA / 多尺度**

- 位置：`train.py` → `FreeMatchMultiLabel.evaluate()`（`mlgcn/freematch.py:244`）：加水平翻转 TTA
  与多尺度平均后再算指标。

**(14) 训练时长 / 迭代数对齐（消除混淆项）**

- 位置：`train.py:356` `num_train_iter`，建议在 `run_experiments.py` 的 G_ratio 扫描中**固定总迭代数**
  （如 6000），或按迭代数而非 epoch 调度 LR，保证不同 ratio 公平可比。

### 4.5 快速落地的最低改动清单（推荐验证顺序）

## 5. 复核清单（跑任何新实验前请先确认）

- [x] 所有实验使用**同一 `--data_dir`**、同一 `split_mode`、同一 `seed`。
- [x] `backbone` 配置与实际运行一致（避免 `train.log` 显示 resnet50 但配置写 resnet101）。
- [ ] G_ratio 扫描**固定总迭代数**，避免“低 ratio 欠训练”干扰结论。

- [ ] 记录 `util_ratio` 曲线：若持续下降或过低，说明伪标签利用不足，优先调阈值与公平项。
