# 01 · 可行性分析（FreeMatch + ML-GCN + ASL 半监督多标签）

## 1. 结论（先给结论）

**可行，且您的数据规模（15 类、约 2200 张训练图）非常适合该组合。** 三个库的"核心逻辑"可以
无缝拼装，前提是把 FreeMatch 从**单标签**语境正确改造成**多标签**语境。最大的风险点不在算法可行性，
而在以下几点工程细节（下文逐条分析）：

1. **FreeMatch 的阈值机制必须改为"每类一个阈值"**，否则多标签下会失效。
2. **ML-GCN 依赖预计算的标签相关性矩阵与 GloVe 词向量**，您的数据已提供（`custom_adj.pkl`、`custom_glove_word2vec.pkl`）。
3. **ASL 的负样本硬裁剪需在"软伪标签"场景关闭**（用 `AsymmetricLossSoft`），否则会抑制正类学习信号。
4. **GPU 显存仅 4 GB**，决定了骨干网络与分辨率上限（建议 ResNet-50 + 224/384 + 小 batch + AMP）。

---

## 2. 三个组件的定位与为何可编程

| 库 | 核心能力 | 在本项目中被"借用"的部分 |
|----|----------|--------------------------|
| **USB / FreeMatch** | 半监督训练框架：一致性正则 + 伪标签 + EMA 教师 + 自适应阈值 | `mlgcn/freematch.py` 中的阈值更新、掩码、熵正则、EMA teacher |
| **ML-GCN** | 用"标签相关性图"约束分类头，缓解标签缺失/依赖 | `mlgcn/models.py` 中的 `GCNResnet` / `GraphConvolution` 与邻接矩阵生成 |
| **ASL** | 多标签不对称损失，降低海量易分负样本的权重 | `mlgcn/losses.py` 中的 `AsymmetricLoss` / `AsymmetricLossSoft` |

三者**不冲突**：ML-GCN/ASL 负责"多标签建模与损失"，FreeMatch 负责"半监督训练信号"。
他们可以在**同一个前向-后向流水线**里共存，各有独立的前向/损失项。

---

## 3. 技术挑战与应对

### 3.1 FreeMatch 单标签 → 多标签的改造成本（最大挑战）
- **单标签**：`softmax`，每样本一个最大概率，阈值是**每样本一个标量**；伪标签是 `argmax` 的 one-hot。
- **多标签**：`sigmoid`，每样本可有多个正类，`max_prob` 恒≈1.0。若仍用"每样本最大概率"做阈值，
  **永远没有样本会被丢弃 → 阈值机制退化**。
- **应对**：改为**每类独立判断**。对每个 `(样本, 类别)` 对独立比较 `prob[c] > thresh[c]`，
  掩码为 `[U, C]` 的布尔张量。这在 `mlgcn/freematch.py` 与 `mlgcn/freematch.py._per_class_threshold()` 中实现。
- 伪标签由 `sigmoid(logits/T)` 锐化（软标签）或二值化（硬标签），配合 `[U,C]` 掩码做一致性损失。

### 3.2 标签长尾 / 不均衡
您的 15 类频次差异明显（如 `cable`=2266、`person`=122）。FreeMatch 的熵正则中加入了
**fairness 项**（`class_weight = 1/label_hist`）与 ASL 的负样本聚焦，均有助缓解长尾；
训练脚本默认开启 `use_class_balancing`（对稀有类正样本加权）。

### 3.3 邻接矩阵与词向量
- `custom_adj.pkl` 存的是 `{"P": [15,15]}` 条件概率矩阵。ML-GCN 需先二值化（`P ≥ t`），再按论文公式重加权并对称归一化。
  该项目在 `GCNResnet.__init__` 中用 **buffer** 预计算并冻结（`gen_A` + `gen_adj`），
  已验证：对角线均值 ≈ 0.84、每行和 ≈ 1.0，符合预期。
- `custom_glove_word2vec.pkl` 是 `[15, 300]` 词向量，作为 `GCNResnet.inp` 的**可学习**初值。

### 3.4 接口兼容性与依赖冲突
- 三个库的接口差异较大（详见 `docs/03`）。本项目**不直接安装三个库**，而是提取各自核心文件并统一接口，
  避免版本/命名空间冲突；`models.py`、`losses.py`、`freematch.py` 各自独立、无交叉依赖。
- torchvision 图加载使用 `weights=` API（避免 `pretrained=` 弃用告警）。

### 3.5 4 GB 显存
- ResNet-101 + 448 在 4 GB 上不稳定 → 默认 **ResNet-50**，分辨率默认 **224**，`batch_size=8`，开 **AMP**。
- 需要更高分辨率（384）时，用 `batch_size=4`、`eval_batch_size=8`（见 `freematch_mlgcn_resnet50_384.yaml`）。
- 评估用小 batch、`num_workers` 适当即可。

## 4. 预期收益与注意事项
- 半监督（`labeled_ratio=0.2`）通常能在**有标签样本很少**时显著提升 mAP；有标签样本充足时收益有限。
  您需要跑 `G_ratio_*` 实验对比。
- 阈值 `lambda_u`（一致性）与 `lambda_e`（熵）需小范围调参；熵正则过大可能导致模型塌缩到少数类。
- 伪标签噪声会随训练累积，建议配合 ASL warmup（前 3% 迭代接近 BCE）与 EMA teacher。
